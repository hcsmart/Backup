단계별 실무

1

프로세스 정의 — 고객 사무실에서 물어보는 단계

컴퓨터를 켜기 전에 한다. 고객이 하는 말을 "단계 · 들어오는 것 · 나가는 것 · 하는 사람"으로 받아 적는다.

이렇게 묻는다

"주문이 들어오면 제일 먼저 누가 뭘 합니까?"
"영업이 견적번호 받고 제번을 딴다. 제번은 26DGA005A 같은 식."
"그 다음 설계는 뭘 보고 시작합니까? 끝났다는 건 뭘로 압니까?"
"수주서 보고 시작. 조립도·부품도 나오고 PartList 넘기면 끝."
"구매는 PartList 말고 다른 걸 보는 게 있습니까?"
"원재료는 PartList, 구매품은 부품표, 외주가공은 가공공정표."
"Try-Out(S1)이 끝나면 어디에 뭘 남깁니까? 몇 번까지 합니까?"
"검사시트. 보통 2~3차. 승인 나야 출고."

이렇게 적는다

단계들어오는 것나가는 것담당끝나는 조건
수주등록고객 발주서, 견적번호제번, 수주서영업제번 채번
설계계획·실적수주서조립도·부품도, PartList설계PartList 배포
원재료 발주PartList발주서, 입고예정구매입고확정
조립·Try-Out입고 부품, 가공품검사시트, T/O 승인조립승인
흔한 실수 고객이 "우리는 특별한 거 없어요"라고 하면 그냥 넘어가는 것. 그 자리에서 실제 수주서·PartList·검사시트 종이를 한 장씩 받아온다. 종이 양식이 곧 화면이다.
나갈 때 확인 위 표를 고객 현업 책임자가 보고 "맞다"고 서명. 이후 "그거 원래 그렇게 안 해요"는 변경요청서로 받는다.
2

기준정보 설계 — 1단계 표에서 명사를 뽑는 단계

1단계 표에 반복해서 나오는 명사가 기준정보다. 업체, 공정, 자재, 부품, 설비, 사용자, 아이템, 금형타입, 기계사양…

이렇게 묻는다

"업체 코드는 지금 있습니까? 없으면 우리가 V001부터 매겨도 됩니까?"
"ERP에 있는 거 그대로 써달라." → 코드 체계는 고객 것을 따른다.
"고객사와 협력업체가 같은 회사인 경우가 있습니까?"
"있다. 삼수금속은 고객이면서 양산업체." → 구분 컬럼 하나가 아니라 역할 플래그(원자재/면삭/구매품/외주가공)로 간다.
"이 목록은 누가 관리합니까? 바뀌면 누가 고칩니까?"
"생산관리 김과장." → 관리부서 컬럼에 적고, 그 사람에게 권한을 준다.
"초기 데이터를 엑셀로 주실 수 있습니까? 언제요?"
날짜를 받아 적는다. 이게 이 단계의 게이트다.

이렇게 적는다

기준정보키주요 컬럼초기값 출처관리
업체vendor_code (V001)업체명, 구분(고객사/협력업체/자사), 역할 플래그 4개, 소재지ERP 업체 엑셀구매
공정process_code (DL, AS…)공정명, 그룹(설계/가공/조립), 순서공정표 종이생산관리
자재material_code (STD11)자재명, 그룹(원재료/구매품), 비중자재 단가표구매
제번(핵심 키)job_no (26DGA005A)연도2 + 고객약어 + 순번3 + 차수채번 규칙 문서화영업
흔한 실수 "일단 공장 컬럼 넣어두자"처럼 쓸지 안 쓸지 모르는 컬럼을 넣는 것. IPMES에서 공장 항목을 38개 화면에서 뒤늦게 뺐다. 지금 쓰는 것만 넣는다.
나갈 때 확인 고객이 엑셀 초기 데이터를 실제로 보냈는가. 안 왔으면 설계가 끝난 게 아니다.
3

DB 스키마 — 표를 테이블로 옮기는 단계

2단계 기준정보 테이블 + 1단계 각 행마다 트랜잭션 테이블 하나. 화면이 공통으로 보는 집계는 뷰로.

스스로 묻는다

"이 테이블의 한 행은 무엇 하나인가?"
sale_orders 한 행 = 제번 하나. design_plan_steps 한 행 = 제번 + 공정 하나. 이게 안 정해지면 PK가 안 나온다.
"제번 목록을 보여주는 화면이 몇 개인가?"
영업·설계·구매·조립 전부. → job_pool 뷰 하나 만들고 다 그걸 본다. 화면마다 조인하지 않는다.
"이 테이블을 누가 읽고 누가 쓰나?"
기준정보: 로그인 사용자 전원 읽기, 관리부서만 쓰기. → 권한 정책표에 적는다.

이렇게 적는다

테이블한 행PKFK읽기쓰기
vendors업체 하나vendor_code—전원구매
sale_orders제번 하나job_nojobs, vendors, users전원영업
partlist_materials제번+공정+품번(job_no, process_code, part_no)jobs전원설계
job_pool (뷰)진행 중 제번——전원—
IPMES에서 겪은 것 같은 DB에 다른 프로젝트 정책이 들어와 업체 목록이 0건으로 보였다. 테이블마다 정책이 있는지, 테스트 계정으로 select가 되는지 SQL로 확인한다. 화면에서 안 보이면 코드보다 권한을 먼저 의심한다.
나갈 때 확인 백업 스키마 생성. 테스트 계정으로 전 테이블 조회·저장·삭제 SQL 통과.
4

화면 목차·명세 — 화면 하나를 한 줄로 적는 단계

메뉴 = 1단계 프로세스 순서. 화면 한 줄 = 읽는 표 + 쓰는 표 + 버튼. 이 표가 6단계 개발 체크리스트이자 7단계 테스트 목록이다.

이렇게 묻는다

"이 화면에서 저장 누르면 어디에 뭐가 남아야 합니까?"
"발주서 한 줄이 남고 자재표에서 그 품번은 발주됨으로 표시." → 쓰는 표 2개, 상태 컬럼 1개.
"조회만 하는 사람과 등록하는 사람이 같습니까?"
"다르다. 현황은 소장님이 보고 등록은 담당자." → 등록 화면과 현황 화면을 나눈다.
"이 화면을 하루에 몇 번, 한 번에 몇 건 입력합니까?"
"PartList는 한 번에 100줄." → 엑셀 붙여넣기 버튼이 필요하다.

이렇게 적는다

화면파일읽는 표쓰는 표버튼권한
업체관리vendor_management.htmlvendorsvendors찾기 · 지우기 · 신규 · 저장 · 삭제 · 엑셀붙여넣기 · 등록예제구매
원재료 발주material_order_input.htmljob_pool, vendors(원자재), partlist_materials, order_linesorder_lines조회 · 요청추가 · 요청삭제 · 발주저장 · 발주취소 · 첨부구매
조립실적등록assembly_result_input.htmlassembly_job_pool, assembly_steps(없으면 design_plan_steps)assembly_results, assembly_steps, assembly_jobs조회 · 실적등록 · 실적삭제 · 세부공정완료 · 조립완료 · 검사시트조립
흔한 실수 버튼을 나중에 "필요하면 붙이지" 하는 것. 버튼은 곧 쓰는 표다. 표에 버튼이 없으면 그 화면은 조회 화면이고, 조회 화면에 저장 버튼이 생기면 명세가 틀린 것이다.
나갈 때 확인 고객이 메뉴 트리와 화면 명세표를 보고 확인. "이 화면도 있어야 하는데요"는 여기서 다 받는다.
5

공통 모듈 — 한 번 만들어 60번 쓰는 단계

DB 접근, 로그인, 기준정보 CRUD 패턴, 삭제 확인창, 조회 팝업, 엑셀 붙여넣기. 여기서 버그 하나면 화면 60개가 같이 틀린다.

스스로 묻는다

"기준정보 화면 15개가 서로 다른 코드일 이유가 있나?"
없다. → MESDB.master({table, pk, map}) 하나로 조회·저장·삭제·자동새로고침을 다 처리한다. 화면은 컬럼 매핑만 적는다.
"저장 후 화면이 자동으로 바뀌어야 하나, 사용자가 조회를 눌러야 하나?"
자동. → notify/onChange로 같은 표를 보는 화면이 같이 갱신된다. 이걸 화면마다 만들면 반드시 빠뜨린다.
"파일을 고쳤는데 고객 화면이 안 바뀌면?"
캐시. → 모든 JS는 ?v=APP_VER로 부르고, 파일 고치면 번호를 올린다. 규칙을 문서에 적어둔다.

공통 모듈 목록 예

파일역할화면에서 쓰는 방법
mes_db.jsDB 접근, 기준정보 CRUD, 변경 알림, 버전MESDB.table('vendors').select(...), MESDB.master({...})
mes_auth.js로그인, 토큰, 권한index.html에서만 로드. 화면은 부모 토큰을 읽음
mes_ctx.js삭제 확인창, 버튼 색 규칙자동. 삭제 버튼 누르면 확인창
mes_lookup.js업체·품번 조회 팝업MESLK.open('vendor', cb)
mes_paste.js엑셀 붙여넣기버튼 하나 붙이면 끝
나갈 때 확인 템플릿으로 기준정보 화면 3개(업체·공정·자재)를 만들어 7단계 1차 하네스를 통과.
6

화면 개발 — 명세표 한 줄씩 닫는 단계

기준정보 15개 → 영업 → 설계 → 구매 → 조립 → 원가 순서. 4단계 명세표의 행을 하나 만들 때마다 체크한다. 진행률은 "닫은 행 / 전체 행".

화면 하나 만드는 순서

1) 템플릿 복사 → 파일명·제목·breadcrumb 수정

2) 명세표의 "읽는 표"만큼 조회 코드 → 화면에 목록이 뜨는지 확인

3) 명세표의 "버튼" 하나씩: 버튼 이름 = 메시지 (저장 → "저장했습니다", 삭제 → "삭제했습니다")

4) 실패 메시지는 원인 + 조치: "저장 실패" 가 아니라 "저장 실패: 등록되지 않은 제번입니다. 영업관리 › 수주등록에서 먼저 등록하세요."

5) 등록예제 버튼: 이 화면을 처음 보는 사람이 눌러보면 채워지는 샘플 값

6) 7단계 1차 하네스 돌리고 명세표 행 닫기

고객이 자주 하는 말과 대응

"S1이 뭐예요? 우리는 Try-Out이라고 하는데."
1단계 용어 정의서에 있었어야 할 말. 지금 나오면 용어 정의서에 추가하고 전 파일 일괄 치환(IPMES: 15개 파일).
"설계랑 조립이 같은 화면인 게 이상해요."
4단계에서 "쓰는 사람이 다른가"를 안 물어본 결과. ?mode= 파라미터로 화면을 나눈다.
나갈 때 확인 모듈(영업/설계/구매/조립) 하나 끝날 때마다 7단계 2차 시뮬 통과.
7

검증 — 싼 것을 자주, 비싼 것을 인도 전에

세 가지 검증은 잡는 결함이 다르다. 하나가 다른 걸 대신하지 않는다.

무엇을, 언제

검증어떻게언제걸리는 시간잡는 것못 잡는 것
1차 버튼 하네스가짜 브라우저(jsdom) + 가짜 DB. 버튼을 전부 자동으로 눌러봄. node sim_buttons.js화면 하나 만들 때마다26개 화면 30초JS 오류, 저장 눌렀는데 요청 안 나감권한, 실제 DB 오류, 화면 겹침
2차 데이터 흐름수주 1건을 설계→구매→조립→원가까지 흘려서 끝 숫자가 맞는지 확인. node sim_sales.js 등모듈 하나 끝날 때5분모듈 간 키 불일치, 집계 오류 (IPMES 15건)실제 화면 조작감
3차 실브라우저진짜 크롬이 실제 사이트에 로그인해 실제 DB에 대고 클릭. node pw_buttons.js인도 전, 고객 지적 재현26개 화면 10분가려진 버튼, 확인창, iframe, 권한—

결과는 이렇게 읽는다

OK 사업부정보 저장 ok req=[POST business_divisions] msg="BN005 항목을 저장했습니다" → 정상

FAIL 업체관리 저장 ok req=[] msg="저장했습니다" → 메시지는 성공인데 요청이 없다. 화면이 거짓말하는 경우. 가장 위험.

FAIL 단가변동등록 삭제 ok req=[] msg="삭제할 행을 선택하세요" → 하네스가 행을 못 골랐을 수도 있다. 사람이 한 번 눌러보고 판단.

고객이 "안 돼요"라고 할 때 코드부터 열지 말고 순서대로: ① 요청이 서버까지 갔나(로그) ② 권한이 있나(SQL) ③ 그 다음 코드. IPMES 업체 0건은 ②였고, 삭제 안 됨은 ①에서 요청 자체가 없었다.
나갈 때 확인 1·2·3차 결과 파일 첨부. FAIL 0건이거나, 남은 결함 목록에 고객이 합의.
8

시연 데이터·인도·검수 — 빈 화면을 보여주지 않는 단계

고객은 빈 목록으로는 시스템을 이해하지 못한다. 수주부터 실적까지 이어진 가상 제번을 3건 이상 넣고, 그 제번으로 전 화면을 시연한다.

규칙: 품번·재질·업체는 기준정보에 있는 코드만 쓴다(FK 오류 방지). 비고에 "시연용"을 적고 제번 접두어를 정해 한 번에 지울 수 있게 한다. 두께·가로·세로처럼 계산에 쓰는 값은 비우지 않는다.

검수 운영

"이거 왜 안 되죠?" 를 회의 중에 받으면?
그 자리에서 고치지 않는다. 점검표(QA-001) 행으로 받아 적고 번호를 준다. 다음 주 리뷰에서 닫는다.
고객 여러 명이 각자 연락하면?
창구는 HC Smart 하나(QA-002). 월 개발 → 수 스테이징 → 목 문서 → 금 14시 화면공유 리뷰.
나갈 때 확인 점검표 전 항목 고객 확인. 인도 패키지(플랫 ZIP, 버전 기재), 백업 스키마와 복원 절차 인계.

자주 하는 질문

기준정보부터 만들면 안 되나? 고객이 업체 목록은 이미 갖고 있는데.
목록은 받아두되 컬럼은 1단계 뒤에 정한다. "고객사이면서 양산업체" 같은 건 프로세스를 들어야 안다.
화면 60개를 다 명세표로 쓰면 시간이 너무 걸리지 않나?
한 줄에 1분. 60줄이면 1시간. 명세 없이 만들었다가 38개 화면에서 컬럼 빼는 데 며칠 걸렸다.
하네스 세 개를 다 해야 하나?
1차는 매번(30초). 2차는 모듈당 1회. 3차는 인도 전 1회 + 고객 지적 재현 때. 1차만 해도 절반은 잡힌다.
고객이 1단계 서명을 안 해주면?
"이대로 만들겠습니다"라고 메일로 보내고 회신 없으면 그 메일이 서명이다. 기록이 없는 게 문제지 형식이 문제가 아니다.
